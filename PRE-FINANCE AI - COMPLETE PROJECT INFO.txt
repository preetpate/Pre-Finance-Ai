SECTION 1 — WHAT THIS PROJECT IS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Pre-Finance AI is a completely offline, free, full-stack AI-powered document
intelligence platform. Users upload PDF, DOCX, or TXT documents, then ask
questions about them in plain English. The AI answers with source citations
pointing to exact page numbers from the uploaded documents.

ZERO paid APIs. ZERO cloud AI. Everything runs on your local machine.

Core AI workflow:
  User uploads PDF/DOCX/TXT
    → Text extracted (PyMuPDF / python-docx)
    → Split into chunks (Recursive Splitter)
    → Embeddings created (Sentence Transformers — local)
    → Stored in FAISS vector database (local)
    → User asks question
    → Top matching chunks retrieved from FAISS
    → Sent as context to Ollama (local LLM)
    → Answer + source citations returned to user

This is called RAG (Retrieval-Augmented Generation) architecture.

SECTION 7 — SECURITY IMPLEMENTATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Password:
  Algorithm: Argon2id (via passlib)
  Never stored plain text, never logged
  Validation: min 8 chars, 1 uppercase, 1 digit (Pydantic + frontend)

JWT:
  Library: python-jose[cryptography]
  Algorithm: HS256
  Secret: SECRET_KEY in .env (min 32 chars)
  Expiry: 60 minutes (ACCESS_TOKEN_EXPIRE_MINUTES)
  Payload: { sub: user_id, role: "user"|"admin", exp: timestamp }
  Storage client-side: localStorage (key: pf_token)

Admin Account:
  Created ONLY by seed_admin() at startup — never via public /auth/register
  Controlled by ADMIN_EMAIL + ADMIN_PASSWORD in .env
  Role "admin" cannot be self-assigned

Role Guards:
  get_current_user() — verifies JWT, checks user exists, checks is_active
  require_admin()    — calls get_current_user() then checks role == "admin"
  Frontend guards: requireAuth(), requireAdmin() in api.js (redirect on fail)
  NOTE: Frontend guards are convenience only. Backend always verifies independently.

Document Privacy:
  Every document stores user_id
  GET/DELETE check: doc.user_id == current_user.id OR current_user.role == "admin"
  Users cannot access each other's documents, even by guessing IDs

File Uploads:
  Extension whitelist: .pdf, .txt, .docx
  MIME type check: application/pdf, text/plain, .docx MIME
  Max size: 50 MB (configurable via MAX_FILE_SIZE_MB in .env)
  Stored with UUID filename (original name saved in DB only)
  Served as downloads only — not executed

CORS:
  Allowed origins: http://localhost:5500, http://127.0.0.1:5500
  Additional origins configurable via FRONTEND_ORIGIN in .env
  Credentials: allowed

Input Sanitization:
  All inputs go through Pydantic validators on the backend
  HTML displayed in frontend uses escHtml() to prevent XSS
  Document content treated as untrusted — not passed raw to prompts without limits

SECTION 11 — FRONTEND: WHAT EACH PAGE DOES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

login.html
  - Two-column: brand panel (left) + form (right)
  - Brand panel has purple glow orbs, 4 feature bullets
  - Form: email + password + show/hide toggle
  - On success → redirects admin to admin/dashboard, user to dashboard
  - Calls: POST /auth/login → saves token + user to localStorage

register.html
  - Same two-column layout
  - Password strength meter (4 segments: weak/fair/good/strong)
  - Validation: name required, valid email, 8+ chars, passwords match
  - Calls: POST /auth/register → redirects to login.html

pages/dashboard.html
  - Sidebar with active state on "Overview"
  - 4 stat cards: total docs, conversations, indexed docs, AI model info
  - Recent documents list (last 5)
  - Recent conversations list (last 5)
  - Quick action buttons: Upload / New Chat / Edit Profile
  - Calls: GET /documents, GET /chat/conversations

pages/documents.html
  - Drag-and-drop upload zone
  - Browse button for file picker
  - Upload progress bar
  - Document cards grid: icon, name, type, size, status badge, page count
  - Search input + status filter dropdown
  - Delete button with confirmation modal
  - Calls: GET /documents, POST /documents, DELETE /documents/{id}

pages/chat.html
  - Left panel: conversation list (search, rename, delete per item)
  - Right: chat messages area + input
  - Welcome screen with 4 suggested questions
  - Message bubbles: user (purple gradient) + AI (dark card)
  - Citations panel below AI answers
  - Copy button on AI messages
  - Typing indicator (3 bouncing dots)
  - New Chat button clears state
  - Loads conversation by ?id= query param from dashboard
  - Calls: GET /chat/conversations, GET /chat/conversations/{id},
           POST /chat/ask, PATCH rename, DELETE

pages/admin/dashboard.html
  - Admin sidebar (red-orange gradient logo)
  - "Admin Mode" badge in topbar
  - 6 stat cards
  - Doughnut chart: active vs inactive users (Chart.js)
  - Bar chart: document status breakdown (Chart.js)
  - Activity log table: last 10 entries
  - Calls: GET /admin/stats, GET /admin/logs

pages/admin/users.html
  - User table: avatar initials, name, email, role badge, status badge
  - Joined date + last login
  - Activate/Deactivate button per row (skips own account)
  - Search by name/email + filter by role + filter by status
  - Calls: GET /admin/users, PATCH /admin/users/{id}/status

SECTION 12 — FRONTEND JS: api.js and ui.js
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

api.js — API_BASE = 'http://localhost:8000'
  Auth object:
    Auth.getToken()         reads localStorage key 'pf_token'
    Auth.setToken(t)        saves token
    Auth.getUser()          parses localStorage 'pf_user' JSON
    Auth.setUser(u)         saves user object
    Auth.isLoggedIn()       true if token exists
    Auth.isAdmin()          true if user.role === 'admin'
    Auth.save(tokenResp)    saves both token and user
    Auth.clear()            removes both

  apiFetch(path, options)   core wrapper: adds Bearer header, handles 401 auto-logout
  apiUpload(path, formData) for file uploads (no Content-Type so browser sets boundary)

  AuthAPI.register(name, email, password)
  AuthAPI.login(email, password)
  AuthAPI.logout()
  AuthAPI.me()
  AuthAPI.changePassword(current, new)

  DocsAPI.list()
  DocsAPI.upload(file)
  DocsAPI.delete(id)
  DocsAPI.get(id)

  ChatAPI.listConversations()
  ChatAPI.getConversation(id)
  ChatAPI.rename(id, title)
  ChatAPI.delete(id)
  ChatAPI.ask(question, conversation_id)

  AdminAPI.stats()
  AdminAPI.users()
  AdminAPI.setUserStatus(id, is_active)
  AdminAPI.documents()
  AdminAPI.logs(limit)

  Route guards:
    requireAuth()       — redirects to login.html if not logged in
    requireAdmin()      — redirects if not logged in or not admin
    redirectIfLoggedIn() — redirects logged-in users away from login/register

ui.js
  Toast.success/error/warning/info(message, duration)
    — Shows toast at bottom-right, auto-removes after duration ms
    — Style: dark card + colored left border

  confirm(title, message) → Promise<boolean>
    — Modal overlay with Cancel + Confirm buttons
    — Returns true/false

  Loader.show() / Loader.hide()
    — Full-page overlay with spinner

  Theme.get() / Theme.apply(theme) / Theme.toggle() / Theme.init()
    — Saves to localStorage key 'pf_theme'
    — Applies data-theme="dark"|"light" to <html>

  initSidebarToggle()   — mobile hamburger menu
  autoResize(el)        — textarea auto-height
  formatDate(iso)       — "Jan 15, 2024"
  formatDateTime(iso)   — "Jan 15, 2:30 PM"
  formatBytes(bytes)    — "1.2 MB"
  initials(name)        — "John Doe" → "JD"
  setActiveNav(page)    — adds .active class to matching nav item
  renderSidebarUser()   — fills name/role/initials from Auth.getUser()
  handleLogout()        — calls AuthAPI.logout() then Auth.clear() then redirect

SECTION 13 — DEPLOYMENT OPTIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

RECOMMENDATION: Deploy to Railway (best free option for this stack)

━━ OPTION 1: RAILWAY (RECOMMENDED) ━━
  Website:  https://railway.app
  Free tier: $5 credit/month (enough for small demo)
  Supports:  Python, FastAPI, persistent SQLite, file storage
  Steps:
    1. Push project to GitHub (backend only, or full repo)
    2. Connect Railway to GitHub repo
    3. Set environment variables in Railway dashboard (copy from .env)
    4. Railway auto-detects Python + runs: uvicorn backend.main:app
    5. Frontend: deploy separately to Netlify (free, drag-drop HTML folder)
    6. Update FRONTEND_ORIGIN in Railway env vars to Netlify URL
  Limitation: Ollama (local LLM) cannot run on Railway free tier.
              For demo without AI: mock AI responses or use OpenAI API key temporarily.

━━ OPTION 2: RENDER ━━
  Website:  https://render.com
  Free tier: 750 hours/month (spins down after 15 min inactivity)
  Steps same as Railway
  Problem: Disk storage is ephemeral on free plan — SQLite data lost on restart
  Solution: Use Render's persistent disk ($7/month) OR switch DB to PostgreSQL (free)

━━ OPTION 3: VERCEL (Frontend only) + Railway (Backend) ━━
  Vercel: Deploy frontend/  folder
  Railway: Deploy backend/  folder
  Best for demos and portfolios

━━ OPTION 4: LOCAL DEMO (For Interviews) ━━
  This is the BEST option for AI features.
  Ollama runs locally → AI actually works
  Show on your laptop during interview or screen share
  Run: start_server.bat + ollama serve + Live Server
  Zero cost, full features, full AI

━━ OPTION 5: VPS (Advanced) ━━
  DigitalOcean ($6/month), Hetzner (€3.5/month)
  Full control, can install Ollama
  Best for production use

SUMMARY TABLE:
  Local laptop  → Best for AI features, interviews, development
  Railway       → Best free cloud option, easy deployment
  Render        → Alternative to Railway, free but cold starts
  Vercel        → Frontend only (static HTML)
  VPS           → Production-ready, full Ollama support

IMPORTANT: Ollama local LLM cannot run on free cloud platforms.
  On cloud: either skip AI (show architecture), use a small cloud LLM API,
  or pay for a VPS that supports GPU or at least CPU inference.
